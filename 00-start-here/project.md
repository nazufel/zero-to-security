# Project: your portfolio, day one

## Why this matters

Hiring managers for entry-level roles see hundreds of resumes that say "passionate about security." A link to a portfolio that shows you *doing* security stands out immediately. You'll add to this repo in every module. Today you make it presentable.

## What to build

By the end of this project, your `my-security-portfolio` repo has:

```text
my-security-portfolio/
├── README.md               # who you are and what's here
├── job-research.md         # from lesson 1
├── rules-of-engagement.md  # from lesson 2
├── ticket-practice.md      # from lesson 4
└── stuck-log.md            # from lesson 5
```

## Steps

1. **Rewrite your README.** Replace the one-line placeholder with this structure, filled in honestly:

   ```markdown
   # Your Name: Security Portfolio

   I'm learning security from zero, aiming for a role as a [help desk technician /
   SOC analyst / junior cloud security engineer].

   ## What's here
   | Project | What it shows |
   |---|---|
   | [Job research](job-research.md) | What entry-level security roles actually ask for |
   | [Rules of engagement](rules-of-engagement.md) | How I practice ethically |
   | [Ticket practice](ticket-practice.md) | Writing tickets others can act on |
   | [Stuck log](stuck-log.md) | How I solve problems |

   ## What I'm working on now
   Module 0 of [Zero to Security](link-to-this-course).
   ```

2. **Preview it.** Open your repo on github.com and read it like a hiring manager would. Is it clear in 10 seconds what this is?

3. **Commit and push.**

   ```bash
   git add README.md
   git commit -m "Write portfolio README"
   git push
   ```

## With Claude

Paste your README into Claude and ask:

```text
I'm applying for entry-level security jobs. Review this portfolio README as a
hiring manager would. What's unclear? Don't rewrite it; give me three suggestions.
```

**Check the work:** accept only the suggestions that are true to you. If Claude suggests claiming skills you don't have yet, ignore it. An interviewer will ask about every line.

## Done when

- [ ] Your repo is public and has all five files
- [ ] The README explains who you are and what's there in under 10 seconds
- [ ] You can make, commit, and push a change without looking up the commands

Keep the "What I'm working on now" line up to date as you go. A portfolio that's clearly active beats a perfect one that's been abandoned.
